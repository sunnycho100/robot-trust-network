# Stage contracts and cross-stage keys

Schemas: `contracts/*.schema.json` (generated by `contracts/_build_schemas.py`). The acceptance gate is
`tests/validate.py` + `tests/_ie_checks.py`. A stage implementation should not edit `contracts/`,
`tests/`, `config/demo.yaml` or another stage's folder. If a contract or a check looks wrong, open an issue.

Every stage module is `src/rcd/<folder>/run.py` with `def run(cfg: dict) -> None`, reads inputs only from
`out/` (via `rcd.common.io.load_json`) and the raw data under `data/carda/`, and writes via `save_json(..., contract=...)`.

## Keys shared between stages

- **station**: `"WS10" | "WS20" | "WS30"`. **cycle_id**: `"<NNN>_<MMDD>"` from the file name (`xsens_002_WS10_2023_09_21_...` → `"002_0921"`); the 3-digit id alone repeats across recording days in WS10. Annotation sheet names carry the same prefix.
- **data layout** (normalized by `scripts/fetch_carda.sh`): `data/carda/<ws>/xsens/*.bvh`, `data/carda/<ws>/mp4/*.mp4`, `data/carda/<ws>/annotation_data_*.xlsx`. mp4 names vary (`_in_camera_`, `_out_camera_`, or no side); WS20 has one camera per cycle.
- **element code**: a code from the taxonomy in `s2/elements.json` (e.g. `WALK`, `GET_PART`, `INSERT`, `GET_TOOL`, `FASTEN`, `REACH_FASTENER`, `INSPECT`, `IDLE`). Every station additionally has the pseudo-code `UNOBS` (unobserved part of the ~240 s cycle, `config.observation`), always manual and never automatable.
- **element_key**: `"<station>:<code>"`, the unit that s3 scores and s5 assigns. Its time is the **per-cycle total** of that code in that station (sum of occurrences inside one cycle, averaged over cycles) from `s2/time_study.json → element_stats` (`mean_s`, `standard_s`).
- **group_id** (s4/s6a): `"<station>:<category>"`, a set of element keys that one robot does together, e.g. `"WS30:cobot_screwdriving"`.
- **resource** (s5 assignment): `"human"` or a robot `model` string from the catalog.

## IE fields the gate requires (beyond the schema)

- `s2/time_study.json`: `rating` (Westinghouse, 4 factors), `allowance_breakdown` (ILO items summing to `params.allowance_pfd`), `pmts` (`system`, `rows[{code, tmu, pmts_s, observed_s}]`), `spc` (per station I-MR: `observations_s`, `ucl_s`, `usl_s`=takt, `cpu`), `lean` (`rows[{code, class VA/NNVA/NVA, waste}]`, `va_ratio`).
- `s4/candidates.json`: `ranking` (`method` AHP+TOPSIS, `consistency_ratio`), each passed model has `cell_space` (`K_mm_s`, `T_s`, `C_mm`, `separation_mm`, `footprint_m2`, `aisle_allowance`, `total_m2`).
- `s5/allocation.json`: `line_balancing` (`heuristics[{name RPW/LCR/COMSOAL, cycle_time_s, station_loads_s, balance_efficiency, balance_delay, smoothness_index}]`, `exact`, `theoretical_min_stations`), `worker_machine[{station, human_s, robot_s, interaction_s, cycle_s, human_idle_pct}]`, one scenario with `recommended: true`.
- `s6b/des_results.json`: each scenario has `littles_law{throughput_per_s, flow_time_s, avg_wip}`; `validation{des_baseline_throughput, analytic_baseline_throughput}`.
- `s7/roi.json`: each scenario has `crf{i, n, value}` and `annualized_capex_usd`.
