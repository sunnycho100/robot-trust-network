# 아키텍처: 구성 요소별 정리

각 요소는 따로 만들고 따로 테스트할 수 있는 단위입니다. C1과 C2는 나머지가 올라갈 바닥이고, C3부터 C5가 이 프로젝트의 실제 기여입니다. 단계를 나눠서 초반부터 돌아가는 게 나오도록 했습니다.

---

## C1. 시뮬레이션 환경
로봇이 사는 세상. 물리 엔진 없이 시작합니다.

- **1단계: 터미널만.** 집마다 하나씩, Python 프로그램 두 개가 무엇을 하는지 출력만 합니다. 시뮬레이터 없음. 메시지와 신뢰 흐름 전체를 여기서 다 테스트할 수 있습니다.
- **2단계: 간단한 물리.** Gazebo나 MuJoCo에 로봇 두 대. 이제 요청이 실제 움직임으로 이어집니다(현관까지 이동). MuJoCo가 가볍고 반복 실험이 빠르고, Gazebo는 ROS 2와 바로 붙습니다.
- **3단계: Isaac Sim.** 데모 영상용으로 사실적인 집 안에 휴머노이드 두 대. NVIDIA GPU가 필요하니 마지막에, 선택 사항으로 둡니다.

완료 기준: 2번 집의 요청으로 1번 집 로봇이 시뮬레이터 안에서 실제로 움직인다.

## C2. 전송 계층 (메시지가 어떻게 가는가)
한 집에서 다른 집으로 메시지가 전달되는 경로.

- **1단계: 같은 ROS 2 네트워크.** 두 로봇을 한 ROS 2 그래프에 두고 토픽으로 주고받습니다. 가장 쉽고, 일부러 틀린 구조입니다(서로의 모든 정보가 다 보임).
- **2단계: 집 분리.** 집마다 `ROS_DOMAIN_ID`를 다르게 줘서 서로의 토픽이 안 보이게 합니다. 두 집을 잇는 건 양쪽이 접속하는 MQTT 서버 하나뿐입니다. 이게 현실적인 구조입니다.
- **3단계: 불안정하고 서로 다른 네트워크.** 두 집이 다른 인터넷 사업자를 쓰는 상황. 메시지가 늦게 오거나, 순서가 바뀌거나, 사라지고, 한쪽 집이 아예 끊길 수도 있습니다. 로봇이 답을 기다리며 멈춰 있지 않고 안전한 기본 동작으로 돌아가는지 확인합니다.

완료 기준: 요청 도중에 연결을 끊어도 두 로봇 모두 안전하고 예측 가능한 상태로 남는다.

## C3. 신원 확인과 메시지 형식
누가 요청하는지 증명하고, 어느 브랜드든 읽을 수 있는 형태로 말하기.

- 고정된 요청 형식: 누가, 어느 집에서, 어떤 동작을, 왜, 언제.
- 로봇마다 자기 키로 메시지에 서명하고, 어떤 키가 어떤 로봇인지 등록해 둡니다. 옆집 로봇인 척할 수 없게 됩니다.
- 재전송 방지: 예전에 가로챈 "문 열어" 메시지를 나중에 다시 보내도 통하지 않게 합니다.

완료 기준: 위조되거나 재전송된 메시지는 거절되고, 정상 메시지는 통과한다.

## C4. 문지기 (판단 계층)
집마다 하나씩 도는 프로그램. 이 프로젝트의 핵심입니다.

- 확인된 요청을 받아 주인의 규칙과 신뢰 점수에 비춰 봅니다.
- 결과는 셋 중 하나: 따른다, 일부만 따른다, 거절한다. 이유도 함께 남깁니다.
- 금지된 동작은 신뢰 점수가 아무리 높아도 계속 금지입니다(현관문, 카메라, 주인을 위험하게 만드는 것).
- 허용된 요청은 로봇의 평소 ROS 2 명령으로 넘깁니다.

완료 기준: 규칙이 다른 두 집이 같은 요청에 다른 답을 낸다.

## C5. 신뢰 네트워크
각 집이 바깥 로봇을 얼마나 믿는지, 그리고 그 값이 어떻게 변하는지.

- 시작 점수는 주인이 정하고, 문제없이 끝난 일은 점수를 올리고, 실패하거나 거절된 요청은 내립니다.
- 점수 구간에 따라 그 로봇이 요청할 수 있는 범위가 정해집니다.
- 이후 확장: 이웃을 통해 신뢰가 전달됩니다("3번 집이 이 로봇을 보증함"). 여기서부터 목록이 아니라 네트워크가 됩니다.

완료 기준: 한 로봇이 반복된 정상 거래를 통해 정보 열람 수준에서 도움 요청 수준까지 올라간다.

## C6. 주인 화면
사람이 보는 부분.

- 모든 요청과 결정을 쉬운 문장 한 줄로 기록합니다.
- 기록과 현재 신뢰 목록을 보여 주고 규칙을 바꿀 수 있는 간단한 웹페이지.

완료 기준: ROS 2를 전혀 모르는 사람이 기록만 읽고 무슨 일이 있었는지 이해한다.

## C7. 시나리오와 평가
이 프로젝트를 무엇으로 판단할지.

- 고정 시나리오: 모르는 로봇의 정보 요청, 이웃의 도움 요청, 금지된 요청, 위조된 발신자, 작업 도중 연결 끊김.
- 보고할 숫자: 막아 낸 위험한 요청, 통과시킨 정상 요청, 문지기 때문에 늘어난 판단 시간, 연결이 끊겼을 때의 동작.

완료 기준: 전체 시나리오가 자동으로 돌아가고 발표나 논문에 넣을 표가 나온다.

---

**작업 순서:** C1 1단계 + C2 1단계 + 대충 만든 C4면 터미널에서 도는 데모가 먼저 나옵니다. 그다음 C3로 단단하게 만들고, C2 2단계로 집을 분리하고, C5로 신뢰를 움직이게 하고, C1 2단계로 실제 움직임을 붙이고, C6과 C7로 보여 줄 수 있게 만듭니다.
